## ข้อผิดพลาดที่แก้ระหว่างตรวจ

- แยกสตรีมเสียง Opus สำหรับ WebRTC ออกจาก HLS/MSE เพื่อไม่ให้เลือกผู้ส่งที่มีแต่เสียง
- กล้องจำลองที่ใช้ไฟล์เดียวกันแบ่งปัน producer เดียว แก้ FFmpeg return-path ชนกันเมื่อเปิดหลายช่อง
- ใช้ input template วนไฟล์สาธิตต่อเนื่อง และตรวจวิดีโอข้ามรอบไฟล์จริง
- ป้องกัน timer เก่าหยุด PTZ lease ที่ต่ออายุแล้ว และไม่รายงาน PTZ รุ่นที่ไม่รองรับว่าสำเร็จ
- ปิด transport เบื้องหลังเมื่อขยายภาพหรือแอปเข้าพื้นหลัง และเพิ่ม watchdog สำหรับภาพค้าง
- แก้โครงสร้าง runtime ARM64 ให้ประกอบแพ็กเกจเป้าหมายจาก repository ที่ตรวจลายเซ็น โดยไม่ติดตั้ง emulator แบบ privileged บนเครื่องผู้ใช้

## เพิ่มเติม 1 พฤศจิกายน 2026: ตัวเปิด Windows live

- เพิ่ม Compose และตัวเปิดโหมดจริงบน Windows พอร์ต `127.0.0.1:17801` โดยใช้ images amd64 ที่ตรวจไว้เดิม ไม่แก้ backend/web/APK/NAS image
- เริ่มจาก volumes ใหม่ได้จริง: bootstrap ระบุ `mode=live`, `authenticated=false`, `needsSetup=true`; health ตอบ `status=ok`
- API รายการกล้องก่อนเข้าใช้ตอบ HTTP 401
- ตรวจ Docker port bindings: เฉพาะเว็บที่ 127.0.0.1:17801 ตัว gateway ไม่มีพอร์ตเผยแพร่
- รีสตาร์ต app แล้วสถานะรอตั้งเจ้าของและรหัสเริ่มต้นเดิมคงอยู่ ตรวจเปรียบเทียบภายในโดยไม่แสดงรหัสในรายงาน
- ตัวเปิด `Start-Live.ps1 -NoBrowser` และตรวจสถานะ `Check-System.ps1 -Mode windows-live` ทำงานผ่าน
- เจ้าของต้องเปิดตัว launcher เพื่อดูรหัสและตั้งบัญชีเอง ไม่สร้างบัญชีทดสอบในฐาน live นี้ ไม่เปิด discovery หรือกรอก Camera Account ให้เจ้าของ
- ยังไม่ได้ทดสอบภาพ/เสียง/หมุนของกล้องจริง หรือการเข้าถึงกล้องจาก Docker Desktop ผลนี้ยืนยันเพียงความพร้อมของเครื่องกลางสำหรับเริ่มตั้งค่า
- ชุด ZIP ปรับรวมตัวเปิดและเอกสารใหม่ โดยไม่แนบ volumes หรือรหัสเริ่มระบบ

## เพิ่มเติม 1 พฤศจิกายน 2026: ผลเชื่อม Tapo ไม่หายหลัง 5 วินาที

- เดิมผลเชื่อมแสดงเพียง toast 5 วินาที ทำให้เจ้าของเห็นเหมือนไม่มีผล เปลี่ยนให้มีสถานะกำลังเชื่อมและผลสำเร็จ/ผิดพลาดค้างใต้ปุ่มในฟอร์มเพิ่มด้วย IP พร้อม timeout ฝั่งเว็บ 35 วินาที (ฝั่งระบบกลาง 25 วินาที)
- แยกข้อความกรณี ONVIF ปฏิเสธ HTTP/ข้อมูลยืนยัน/timeout โดยไม่แสดง response กล้อง, รหัสผ่าน หรือ URL ที่มี credentials
- Go tests รวม 14 ชุด และ go vet ผ่าน เพิ่มตรวจมาตรฐาน nonce/digest และตรวจการจำแนก error โดยไม่เผยข้อมูลลับ TypeScript/production build ผ่าน
- ตรวจกล้องจริง .91/.92 ด้วย `GetSystemDateAndTime` ที่ไม่ต้องใช้บัญชี: HTTP 200 จาก Windows และ Docker network ของ app ไม่เปลี่ยนการตั้งค่าหรือหมุนกล้อง
- ใช้ปุ่มเชื่อมต่อในฟอร์มที่เจ้าของกรอกสำหรับ Tapo91 ได้ HTTP 400 SOAP fault กลุ่มข้อมูลยืนยันไม่ผ่าน ยังไม่มีภาพจริงและยังเพิ่มกล้องไม่สำเร็จ ไม่อ้างว่ารหัสผ่านผิดแน่นอน
- ตรวจข้อสงสัยเรื่อง URI ของ nonce แล้วพบว่าถูกต้องอยู่ก่อน ไม่ได้แก้รูปแบบ nonce และไม่ยืนยันว่าเป็นต้นเหตุ
- สร้าง app images และแพ็กเกจใหม่สำหรับ Windows/ARM64 พร้อมเอกสารปัจจุบัน APK ไม่เปลี่ยน
- ตรวจ UI ในแท็บแยกด้วย IP ตัวอย่างที่ระบบปฏิเสธก่อนติดต่อเครือข่าย ข้อผิดพลาดใต้ปุ่มยังแสดงหลังผ่านไปมากกว่า 5 วินาที และไม่เพิ่มกล้องลงทะเบียน ล้างฟอร์มทดสอบแล้วเตรียม IP/ชื่อบัญชีจริงให้เจ้าของ โดยเว้นรหัสผ่านไว้กรอกเอง ไม่ทดสอบรหัสผ่านเจ้าของใหม่หรือเปิดเผยรหัสในรายงาน

### ตรวจต่อ: แยก fault ยืนยันบัญชี

- ส่งเฉพาะ WS-Security digest โดยถอด HTTP Basic header ที่ซ้ำออกตามรูปแบบ client อ้างอิงของ go2rtc ไม่มีการเปลี่ยนบัญชี กลไก nonce/digest และการเข้ารหัสที่เก็บยังเดิม
- เพิ่ม fault code ที่เลือกจากรายการคงที่เท่านั้น ไม่ส่ง raw SOAP body ให้ผู้ชม
- Go tests 14 ชุดและ go vet ผ่าน รวมตรวจไม่มี HTTP Authorization header ซ้ำขณะ SOAP digest ถูกต้อง
- ทดสอบผ่านฟอร์มเดิมที่เจ้าของกรอก: กล้อง Tapo91 ตอบ **HTTP 400 · NotAuthorized** หลังปรับ ยังค้างรอเจ้าของตรวจ Verify ในแอป Tapo ยังไม่ตรวจภาพและไม่รับรองว่าเกิดจากรหัสผ่านผิดเพียงอย่างเดียว

### ตรวจต่อหลังเจ้าของแจ้ง Verify ผ่าน

- เจ้าของแจ้ง Verify ผ่าน แต่ยังไม่ได้รับ Username จริง หน้าต่างที่เจ้าของอธิบายมี Not Now / Update Password จึงยังไม่ยืนยันว่าคู่บัญชีที่อยู่ใน CameraHub ตรงกับกล้อง
- ONVIF client ใช้ printable 16-byte nonce และ SOAP headers แบบ client อ้างอิง go2rtc ทดสอบ digest/nonce/headers ผ่าน แต่กล้องจริงยังตอบ NotAuthorized ไม่อ้างว่าแก้สาเหตุได้จากการเปลี่ยนนี้
- เพิ่มตรวจ RTSP ด้วยคู่บัญชีเดียวกันเมื่อ ONVIF ปฏิเสธ ผ่าน gateway ของจริง โดย PATCH stream ใน memory และ DELETE ภายหลัง ไม่บันทึก URL ลง config ด้วย PUT และไม่เพิ่มกล้องจริงอัตโนมัติ
- ผลจริงกับ Tapo91: ทั้ง ONVIF และ RTSP ปฏิเสธคู่บัญชีที่กรอก (RTSP ส่ง `wrong user/pass`) หยุดลองซ้ำเพื่อรอ Username จริง/ภาพหน้าบัญชีจากเจ้าของ ไม่สรุปว่ารหัสผ่านที่ใช้ Verify ผิด
- Go tests รวม 15 ชุดและ go vet ผ่าน รวมกรณี RTSP accepted/rejected/unavailable, การ cleanup และการไม่เผยข้อมูลลับ App images/ZIP อัปเดตให้ตรงกัน ภาพ/เสียง/หมุนของกล้องจริงยังไม่ผ่านการตรวจ

### เพิ่ม Tapo91 สำเร็จและแก้การเลือกโปรไฟล์ภาพ

- ภาพจากเจ้าของแสดง Username `tapo-user-1` ซึ่งต่างจากที่กรอก `tapo-user-01` แก้ชื่อเพียงอย่างเดียวผ่าน UI ใช้รหัสผ่านเดิมแล้วเพิ่มกล้องสำเร็จ ได้รุ่น Tapo C520WS และข้อมูลความสามารถ PTZ การยืนยันก่อนหน้านี้จึงไม่ใช่หลักฐานว่ารหัสผ่านผิด
- การอ่านความสามารถไม่ถือว่าตรวจภาพ/เสียง/หมุนผ่าน: ภาพจริงยังไม่ขึ้น ตรวจ gateway แบบไม่แสดง URL/credentials พบ low เลือก `/stream8` และ timeout
- แก้ ONVIF profile selection ให้ใช้ `/stream1` เป็น high และ `/stream2` เป็น low เมื่อประกาศไว้ ไม่เขียนทับ low ด้วย auxiliary profile และหยุดเรียกโปรไฟล์เมื่อพบคู่หลัก/ย่อยแล้ว
- ปุ่มตรวจภาพ live Tapo อ่านข้อมูล profiles ใหม่จากบัญชีที่เก็บไว้ พร้อมตรวจรหัสกล้องก่อน merge เพื่อไม่ผูกกับกล้องอื่นที่มาใช้ IP เดิม
- Go tests 15 ชุดและ go vet ผ่าน รวม fixture ที่ stream8 อยู่ก่อน main/sub และ profile ส่วนเกินหลัง sub ไม่ถูกเรียก
- ช่วงตรวจต่อ Windows และ Docker ติดต่อ .91:2020/.91:554 ไม่ได้ (connection refused) แต่ .92 ยังตอบทั้งสองพอร์ตและ ONVIF time query จึงหยุดเปิดภาพซ้ำ รอเจ้าของตรวจ Camera Account/ภาพสดใน Tapo ไม่ยืนยันว่าแก้ภาพจริงสำเร็จ
- ไม่เปิดเสียงหรือสั่งมอเตอร์ ไม่ทำเครื่องหมายตรวจรับเสียง/หมุน และไม่เพิ่ม Tapo92 จากการคาดเดาบัญชี
