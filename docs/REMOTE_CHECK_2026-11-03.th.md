# ตรวจต่อจากระยะไกล — 3 พฤศจิกายน 2026 ช่วงเย็น

เจ้าของขอให้ดำเนินการโดยไม่ต้องอยู่ที่ออฟฟิศ รอบนี้ตรวจจากเครื่องกลางและกล้องจริง ใช้บัญชีเดิม ไม่มีการรีเซ็ต เปลี่ยนเฟิร์มแวร์ สั่งตัดไฟ หรือเปลี่ยนรหัสผ่าน

## ผลกล้อง

- **Xiaomi ทั้ง 14 กล้องในรายการของเจ้าของ:** รับภาพจริงและอ่านตำแหน่งมอเตอร์ก่อน/หลังสั่งครบสี่ทิศทางผ่านแล้ว H3, C300 Dual 2 และ C300 4 ที่ไม่ผ่านตอนเช้า กลับมาตอบและตรวจผ่านช่วงเย็น
- **Tapo92:** ภาพและสี่ทิศทางผ่านจากผลตรวจรอบเช้า และช่วงเย็นยังเปิดภาพจริง/ถอดรหัสเสียงได้
- **Tapo91:** ยังติดต่อ RTSP554 และ ONVIF2020 ไม่ได้ ตรวจ ARP ตาม MAC ที่เจ้าของส่งไว้พบเพียงรายการเก่าของ IP เดิม ค้นหา WS-Discovery และการค้นหา TP-Link/Kasa แบบไม่ล็อกอินไม่พบตัวนี้ พบ C520WS ที่ Tapo92 เท่านั้น จึงยังไม่สามารถส่งคำสั่งเข้า Tapo91 จากเครื่องกลางได้ ไม่เดาว่าอุปกรณ์เสียและไม่ลองรหัสผ่านกับอุปกรณ์อื่น
- **Indoor Receiver:** เก็บเป็นรายการตัวรับสัญญาณแยก ยังไม่ยืนยันช่องภาพของกล้องที่เชื่อมกับตัวรับ และไม่รับรองว่ารายการนี้มีมอเตอร์

รวม **ภาพ/มอเตอร์ผ่าน15กล้อง** จากกล้อง16ตัว อีก1รายการเป็นตัวรับสัญญาณ รายชื่อบนเว็บจึงยังรวม17 ไม่ได้ลบหรือซ่อนรายการที่ยังไม่ผ่าน

## เสียง

ตรวจรับและถอดรหัสเสียงเป็น PCM จากตัวกลางได้ **15 กล้อง** โดยตรวจประมาณ2วินาทีต่อตัว พบตัวอย่างเสียงที่ไม่เป็นศูนย์ครบ เก็บเฉพาะจำนวนตัวอย่าง/ระดับสัญญาณ/ผลถอดรหัส ไม่เก็บไฟล์เสียงหรือถอดคำสนทนา

ผลนี้ยืนยันว่ามีข้อมูลเสียงและถอดรหัสได้ ไม่ใช่การยืนยันความดัง ความชัด หรือห้องที่ตรงกับเสียงจากการฟังของเจ้าของ ค่า AudioVerified/PTZVerified ของเจ้าของคงเดิม หน้าแอปใช้คำว่า “เจ้าของยังไม่ยืนยัน” เพื่อแยกจากผลตรวจทางเทคนิคที่ทำแล้ว

## ปรับความต่อเนื่อง

1. ภาพหลุดแล้วลองใหม่ต่อเนื่อง เมื่อเปิดหน้านี้อยู่ เว้นช่วงประมาณ10/20/40วินาที และสูงสุดราว1นาทีพร้อมกระจายเวลาระหว่างกล้อง ไม่หยุดถาวรหลังลอง3ครั้ง ไม่ส่งคำสั่งค้นหาLANหรือเคลื่อนมอเตอร์ระหว่าง retry
2. ถ้ากล้องปฏิเสธบัญชี จะไม่ลองรหัสซ้ำอัตโนมัติ ให้แก้บัญชีแล้วกดลองใหม่ ลดโอกาสบัญชีถูกล็อก
3. ป้าย LIVE เปลี่ยนเป็นกำลังเชื่อมต่อทันทีเมื่อสลับไปวิดีโอสำรอง ไม่ใช้สถานะเล่นจากการเชื่อมต่อเก่า เมื่อทราบปัญหาแล้ว ช่องจะคงพื้นดำและสาเหตุระหว่าง retry จนมีภาพเล่นจริง
4. การซิงก์รายชื่อจาก cloud ไม่เลื่อน lastSeen ของวิดีโอให้ดูใหม่ ทั้งกล้องที่ยังเปิดไม่ได้หรือรายการใหม่ ใช้ผลตรวจภาพจริงอัปเดตเวลาแทน เพิ่ม regression test ป้องกันการซิงก์กลบข้อมูลนี้

## การตรวจที่ทำจริง

- ค้นหา miIO จาก Windows แล้วจับคู่เฉพาะรหัสกล้องที่มีในบัญชี ไม่ส่งล็อกอินไปยังอุปกรณ์ที่ไม่รู้จัก ตรวจ CS2 เฉพาะ IP ที่ลงทะเบียน และไม่พบ IP ใหม่ของตัวที่ยังไม่ตอบ
- ใช้ python-kasa สำหรับคำค้นหา TP-Link แบบไม่ใส่ชื่อผู้ใช้/รหัสผ่าน ไม่มีการ update/reset อุปกรณ์ผ่านไลบรารีนี้
- H3/C300Dual2/C3004 ได้วิดีโอจริง แล้วสั่งก้าวสั้นสี่ทิศทางและตรวจเลขตำแหน่งเปลี่ยนจริง ไม่ใช้แค่ข้อความสำเร็จของ HTTP
- ทดสอบหยุด gateway ชั่วคราว แล้วเปิดกลับ ภาพทั้ง4ช่องกลับมาเล่นเองโดยไม่รีเฟรชหน้า (Tapo92/H3/C300Dual2/C3004) ตรวจเพิ่มเติมหลังแก้ป้ายสถานะและคงเหตุผลระหว่าง retry
- Go tests26ฟังก์ชัน+vet และ Web tests6ข้อ/TypeScript/Vite/Dockeramd64build ผ่าน
- รอบตรวจสุดท้ายปิดgatewayแล้วภาพทั้ง4เปลี่ยนพื้นดำพร้อมเหตุผล ป้ายLIVEเป็น0 จากนั้นเปิดgatewayกลับ ภาพทั้ง4เล่นต่อเอง readyState4 โดยไม่รีเฟรชหรือกดลองใหม่ เก็บภาพก่อน/หลังใน .cache/recovery-black-final-evening.png และ remote-four-recovered-evening.png
- เปิดบริการทิ้งไว้และคืนรูปแบบใช้งานเป็นครั้งละ4ภาพ สลับอัตโนมัติทุก30วินาที จำนวน5ชุด รวม17รายการ ไม่ค้างเฉพาะ4กล้องที่ใช้ทดสอบ

หลักฐานส่วนตัวอยู่ .cache/remote-motor-results-evening.json, remote-discovery-results.json, tapo-discovery-evening.json, audio-check-evening.json และ audio-check-extra-evening.json ไม่ใส่ภาพจริง รายชื่ออุปกรณ์ส่วนตัว หรือไฟล์ตั้งค่าบริการใน release

ยังไม่ทดสอบเสียงผ่านลำโพง/จอสัมผัส iPhone/Android จริง, MiTV/AndroidTVจริง, NAS DS223, การดูนอกบ้าน หรือรับรองว่าไม่มีสะดุดตลอดหลายชั่วโมง การที่ Docker เปิดมาหลายชั่วโมงไม่ใช่หลักฐานว่าวิดีโอไม่เคยขาด ชุดติดตั้งZIP/ARM64/APKยังไม่ได้สร้างใหม่รอบนี้
