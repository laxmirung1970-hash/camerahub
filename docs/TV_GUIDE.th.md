# CameraHub TV 1.3.3 — คู่มือรีโมต

หน้าทีวีใช้พื้นชาร์โคล ตัวอักษรสีงาช้าง และจุดเลือกสีส้มอิฐ เริ่มจากภาพ 4 ช่อง ไม่ต้องเปิดรายชื่อกล้องค้างข้างภาพ

## ดูกล้องด้วย 3 ปุ่ม

| ต้องการทำอะไร | ใช้รีโมตอย่างไร |
| --- | --- |
| เลือกมุม | กดลูกศรไปที่กรอบภาพ กรอบสีส้มคือช่องที่เลือก |
| ดูเดี่ยว | กด OK ที่ภาพ |
| กลับ 4 ช่อง | กด Back หรือเลือกปุ่ม **4 ช่อง** |
| เปลี่ยนชุด | กดลงจากแถวล่าง แล้วเลือก **ชุดก่อน / ชุดถัด** |
| เลือกกล้องจากรายชื่อ | เลือก **เลือกกล้อง** → เลื่อนขึ้น–ลง → OK |
| ดูทุกกล้องวนไปเรื่อย ๆ ทีละ 4 ช่อง | ปุ่ม **สลับ: 4 ช่อง** (ค่าเริ่มต้น) เปลี่ยนชุดทุก 30 วินาที ชุดจัดตามกลุ่มกล้องแบบเดียวกับหน้าเว็บ (ตั้งแต่ 1.3.3) |
| ดูทุกกล้องวนไปเรื่อย ๆ ทีละกล้องเต็มจอ | กดปุ่มสลับจนขึ้น **สลับ: ทีละกล้อง** เปลี่ยนกล้องทุก 12 วินาที กด Back ดู 4 ช่องได้ ถ้าไม่กดอะไร 12 วินาทีจะกลับไปวนทีละกล้องต่อ |
| พักภาพที่กำลังดู | กดปุ่มสลับจนขึ้น **สลับ: พัก** (ปุ่มเดียวกันวน 4 ช่อง → ทีละกล้อง → พัก) ระบบจำค่าที่เลือกเมื่อเปิดแอปอีกครั้ง |
| ฟังเสียง | ในภาพเดี่ยว เลือก **เสียง: เปิด** ได้ครั้งละกล้อง |
| ดูรายละเอียดภาพ | ในภาพเดี่ยว เลือก **คุณภาพ** แล้วเปลี่ยนเป็น HD |
| ออกจากแอป | Back จากภาพ 4 ช่อง แล้วเลือกออกจากแอปในหน้าต่างยืนยัน |

ปุ่ม Channel +/−, Page Up/Down หรือ Media Next/Previous เป็นทางลัดเปลี่ยนชุดหรือกล้อง ถ้ารีโมตมีปุ่มเหล่านี้ การใช้งานหลักไม่ต้องพึ่งปุ่มพิเศษ

รายชื่อแสดง **ชื่อที่ตั้งเอง + รุ่นกล้อง** เป็นคนละบรรทัด ชื่อและลำดับมาจากเครื่องกลาง เปลี่ยนชื่อ/เรียงลำดับในมือถือหรือ Windows ได้ ทีวีอ่านการเปลี่ยนแปลงทุก 15 วินาที หากเปิดรายชื่อค้างไว้จะรักษาจุดเลือกเดิม ปิดแล้วเปิดรายชื่อใหม่เพื่ออ่านรายการล่าสุด

**ชุดตามกลุ่ม** (ตั้งแต่ 1.3.3 กติกาเดียวกับหน้าเว็บ): กล้องกลุ่มเดียวกันอยู่ติดกัน และหนึ่งชุดมีกล้องกลุ่มเดียว เช่น กลุ่มที่มี 6 กล้องเป็น 2 ชุด (4 + 2) ด้านบนบอกชื่อกลุ่ม เช่น "ชั้น 2 · ชุด 3 / 6" ลำดับกลุ่มตามกล้องตัวแรกของกลุ่มในลำดับที่ตั้งไว้ ภายในกลุ่มใช้ลำดับเดิม โหมดทีละกล้องและรายชื่อก็เรียงตามกลุ่มเหมือนกัน ตั้งชื่อกลุ่ม/ย้ายกลุ่มจากหน้าเว็บ

## ดูภาพโดยไม่มีเมนูบัง

เมื่อเลือกภาพแล้วไม่กดรีโมตประมาณ 8 วินาที แถบด้านบนและปุ่มด้านล่างจะซ่อน พื้นที่ภาพขยายขึ้น กดรีโมตอีกครั้งเพื่อแสดงเมนู

ระบบพักการเปลี่ยนชุดขณะใช้ปุ่มด้านล่าง เปิดรายชื่อ เปิดกล่องตั้งค่า ดูเดี่ยว หรืออยู่ในโหมดหมุน เมื่อกลับไปดู 4 ช่องจึงเริ่มนับเวลาใหม่ การเปลี่ยนชื่อและการอัปเดตสถานะไม่เปิดสตรีมเดิมใหม่ทั้งชุด

## หมุนกล้อง

1. เปิดภาพเดี่ยวและรอจนเห็นภาพ
2. เลือก **หมุนกล้อง** จะเห็นคำว่า **โหมดหมุนกล้อง** ชัดเจน
3. กดลูกศรค้างเพื่อหมุน ปล่อยปุ่มเพื่อหยุด
4. กด OK หรือ Back เพื่อออกจากโหมดหมุน ก่อนใช้ลูกศรเลือกเมนูต่อ

ลูกศรปกติใช้เลือกหน้าจอ คำสั่งหมุนส่งได้เฉพาะในโหมดหมุนของกล้องที่รองรับและมีภาพแล้ว เมื่อภาพขาด แอปเสียโฟกัส หรือออกจากแอป ระบบส่งหยุดไปยังกล้องตัวที่เริ่มสั่งงาน จำกัดคำสั่งค้างในเครือข่ายทีละหนึ่งรายการ และส่งหยุดก่อนเปลี่ยนทิศหรือกล้อง เครื่องกลางยังมีเวลาหยุดสำรองของตัวเอง

การมีปุ่มหมุนไม่ได้รับรองว่ามอเตอร์ของกล้องทุกตัวหรือทีวีทุกรุ่นผ่านการตรวจจริง

## เมื่อภาพมีปัญหา

- ช่องกล้องใช้พื้นดำและระบุเหตุ เช่น ออฟไลน์ บัญชีหมดอายุ เครื่องกลางยังไม่พร้อม หรือทีวีถอดรหัสไม่ได้
- แสดง **ภาพสด** หลังตัวเล่นได้รับเฟรมภาพและกำลังเล่นแล้ว ไม่ใช้สถานะรายชื่อแทนผลการเปิดภาพ
- หากเครือข่ายหลุด ระบบลองใหม่ด้วยช่วงรอ 10 / 20 / 40 / 60 วินาที และไม่เพิ่มถี่กว่านั้น กล้องที่ทราบว่าออฟไลน์จะรอ 30 วินาทีก่อนลองครั้งแรก
- บัญชีกล้องหมดอายุหรือยังไม่ได้กรอกบัญชี ต้องแก้จากมือถือ/Windows ระบบไม่ลองรหัสผ่านวนไปเรื่อย ๆ
- สิทธิ์ทีวีถูกยกเลิกหรือหมดอายุ ต้องจับคู่ใหม่
- เลือก **ตั้งค่า → ลองเปิดภาพชุดนี้ใหม่** ได้ หากต้องการลองทันที
- ถ้าทีวีเปิด 4 ภาพไม่ไหว ให้ดูเดี่ยวและใช้คุณภาพปกติก่อน จำนวนตัวถอดรหัสพร้อมกันขึ้นกับทีวีจริง
- ภาพ 4 ช่อง: กล้องที่ส่งภาพกว้างเกิน 1280 (เช่น 1080p) ทีวีจะขอให้เครื่องกลางย่อเหลือกว้าง 640 เอง ภาพเดี่ยวยังใช้ภาพเต็มของกล้อง ช่องที่ปิดเสียงไม่ถอดรหัสเสียง
- ตั้งแต่ 1.3.0 ทีวีรับภาพเป็น MP4 ต่อเนื่องสายเดียวต่อช่อง (`GET /api/cameras/{id}/mp4`) แทน HLS ทีวีจึงสำรองภาพได้จริง 3–10 วินาที ถ้าภาพตามหลังสดเกิน 3 วินาทีทีวีจะเล่นเร็วขึ้นเล็กน้อย (1.15 เท่า) จนตามทัน ถ้าเครื่องกลางยังไม่เปิด MP4 (ตอบ 404) ช่องนั้นกลับไปใช้ HLS เอง
- ระหว่างวน 15 วินาทีก่อนเปลี่ยนชุด (โหมดทีละกล้องเริ่มทันทีหลังเปลี่ยนกล้อง เพราะรอบสั้นกว่า 15 วินาที) ทีวีขอให้เครื่องกลางเริ่มต่อกล้องชุดถัดไปไว้ก่อน (`POST /api/cameras/{id}/warm` เครื่องกลางถือภาพไว้ 30 วินาทีหลังภาพเริ่ม) กล้อง Xiaomi ที่ต่อ P2P ช้าจึงขึ้นภาพเร็วขึ้นเมื่อถึงคิว แต่กล้อง Xiaomi ที่ใช้เวลาต่อ 10–20 วินาทีอาจยังขึ้น "กำลังเปิดภาพ" อยู่บ้างในรอบทีละกล้อง 12 วินาที

## ติดตั้งครั้งแรกหรืออัปเดต

ไฟล์ใหม่: `releases/camerahub-tv-1.3.3.apk` และ `.apk.sha256` รุ่น 1.3.3 / versionCode 9 (ชุดตามกลุ่ม และกลับเข้าแอปเองหลังหน้า "อนุญาตจากแหล่งนี้") ทีวีที่มี 1.3.1 ขึ้นไปรับรุ่นนี้จากเครื่องกลางได้เลย (ใช้ได้ดีที่สุดกับเครื่องกลางที่มี `/mp4`, `quality=small` และ `/warm` และตัวกลางวิดีโอที่เปิด `/api/stream.mp4` ใน `allow_paths` กับเครื่องกลางรุ่นเก่ายังเล่นได้ผ่าน HLS) / Android 8 ขึ้นไป ใช้ application ID และกุญแจลงนามเดิมเพื่ออัปเดตทับรุ่นก่อนโดยเก็บการจับคู่ไว้ (อัปเดตด้วย `Install-TV.cmd` ไม่ต้องจับคู่ใหม่)

1. เปิดเครื่องกลาง CameraHub และตั้งค่าเจ้าของระบบให้เรียบร้อย
2. เตรียม **URL HTTPS ของเครื่องกลาง** เช่น URL จาก Tailscale Serve และให้ทีวีเข้าถึง tailnet เดียวกัน
3. นำ APK ไปติดตั้งส่วนตัวบน Mi TV/Android TV แอปจะปรากฏเป็น **CameraHub TV** ในรายการแอปของทีวี ส่งผ่าน Wi-Fi จากเครื่องกลางได้ด้วย `Install-TV.cmd` (เปิด USB debugging บนทีวีก่อน ขั้นตอนสำหรับพนักงาน: [TV_INSTALL_STAFF.th.md](TV_INSTALL_STAFF.th.md))
4. เปิดแอป กรอก URL HTTPS ครั้งแรก
5. เปิด CameraHub จากมือถือ → ตั้งค่า → ทีวีและอุปกรณ์ ตรวจรหัสทีวีให้ตรงแล้วอนุมัติ
6. ครั้งต่อไปเปิดแอปแล้วเริ่มดู 4 ช่องได้ ใช้รหัสผ่านกล้องที่เครื่องกลางเท่านั้น

**`http://127.0.0.1:17801/` ใช้ได้เฉพาะ Windows เครื่องที่รันระบบ ไม่ใช่ที่อยู่สำหรับกรอกบนทีวี** ชุดนี้ยังไม่ได้เปิด HTTPS/Tailscale หรือไปติดตั้งบนทีวีจริงให้โดยอัตโนมัติ จะจัดเส้นทางเครื่องกลางและติดตั้งทีวีเมื่อพร้อมตรวจอุปกรณ์

เมื่อเปลี่ยนเครื่องกลาง การเชื่อมเดิมยังอยู่จนกว่าจับคู่เครื่องใหม่สำเร็จ การกดกลับจากหน้าจับคู่จึงกลับไปดูเครื่องเดิมได้

## อัปเดตจากเครื่องกลาง (ไม่ต้องใช้ USB หรือ Developer options)

ตั้งแต่รุ่น 1.3.1 ทีวีอัปเดตตัวเองจากเครื่องกลางได้ **รุ่นแรกที่มีความสามารถนี้ยังต้องติดตั้งด้วย USB หรือ `Install-TV.cmd` อีกครั้งเดียว** หลังจากนั้นไม่ต้องใช้แฟลชไดรฟ์หรือ adb อีก

ฝั่งทีวี (เจ้าของ):

1. เมื่อเครื่องกลางมีรุ่นใหม่ ทีวีจะขึ้น **"มีรุ่นใหม่ X · กด OK เพื่ออัปเดต"** (ตรวจตอนเปิดแอปและทุก 6 ชั่วโมง ถ้าไม่มีใครกด กล่องจะปิดเองใน 1 นาทีและภาพยังวนต่อ) หรือเลือกจาก **ตั้งค่า → มีรุ่นใหม่ X** ถ้ายังไม่ขึ้นใช้ **ตั้งค่า → ตรวจหารุ่นใหม่จากเครื่องกลาง**
2. กด OK ทีวีดาวน์โหลดจากเครื่องกลาง ตรวจ sha256 ชื่อแอป และเลขรุ่นก่อน ถ้าไม่ตรงจะไม่ติดตั้ง
3. **ครั้งแรกครั้งเดียว** ทีวีจะพาไปหน้า "ติดตั้งแอปที่ไม่รู้จัก" ให้เปิด **อนุญาตจากแหล่งนี้** ของ CameraHub TV แล้วกด กลับ ทีวีจะติดตั้งต่อเอง (1.3.2 กด กลับ แล้วไปหน้าแรกของ Android TV ต้องเปิด CameraHub เองแล้วกดอัปเดตอีกครั้ง 1.3.3 กลับเข้าแอปเอง และถ้าทีวีปิดแอประหว่างนั้น เปิดแอปครั้งต่อไปก็ติดตั้งต่อเอง)
4. หน้าติดตั้งของ Android ถามยืนยัน กด **ติดตั้ง / อัปเดต** แล้วเปิดแอปอีกครั้ง การจับคู่และการตั้งค่าเดิมยังอยู่ (application ID และกุญแจลงนามเดิม Android ไม่ยอมติดตั้งไฟล์ที่ลงนามด้วยกุญแจอื่นทับ)

ฝั่งเครื่องกลาง (คนดูแลระบบ):

1. `scripts/Build-TV.ps1` สร้าง APK แล้วเรียก `scripts/Publish-TVUpdate.ps1` ให้เอง ซึ่งคัดลอก APK รุ่นล่าสุดไปไว้ที่ `tv-update/camerahub-tv.apk` พร้อม `camerahub-tv.json` (versionCode/versionName จาก Gradle) และตรวจว่า APK ตรงกับ `.sha256` และผล build ล่าสุด (ไฟล์ใน `tv-update/` ไม่ถูก commit)
2. สร้าง image ของแอปใหม่ (`docker build -t camerahub/app:1.0.0-amd64 .`) และรีสตาร์ต service app ตามขั้นตอนปกติ (tag image เดิมไว้ย้อนกลับก่อน) image จะมี APK อยู่ที่ `/tv-update` เปลี่ยนที่อยู่ได้ด้วย `APP_TV_UPDATE_DIR` แต่ระบบไม่ยอมเสิร์ฟจากโฟลเดอร์ข้อมูล (`APP_DATA`)
3. API: `GET /api/tv/update` → `{versionCode, versionName, sha256, size}` (404 = ไม่มีอัปเดต) และ `GET /api/tv/update.apk` ใช้ได้เฉพาะทีวีที่จับคู่แล้วหรือเจ้าของ (ลิงก์แชร์ครอบครัวใช้ไม่ได้) sha256 คำนวณจากไฟล์จริงที่เครื่องกลาง ไม่เชื่อค่าจากไฟล์ JSON

**ยังไม่ได้ทดสอบบน Mi TV Stick จริง** โดยเฉพาะหน้า "อนุญาตจากแหล่งนี้" และหน้าติดตั้งของระบบ ถ้าทีวีเปิดหน้าเหล่านี้ไม่ได้ แอปจะแจ้งให้ใช้ `Install-TV.cmd` แทน

## การตรวจรับบนทีวีจริงที่ยังเหลือ

- ขนาดข้อความ/ขอบจอบนทีวีจริง และการเดินโฟกัสด้วยรีโมต Mi TV/Android TV รุ่นที่ใช้งาน
- เปิด HLS กล้องจริง 1 และ 4 ภาพต่อเนื่อง สลับชุด ปลุกทีวี และกลับเข้าแอป
- เสียง การหยุดหมุนเมื่อปล่อยปุ่ม การหลุดเครือข่ายจริง และจำนวนตัวถอดรหัส
- HTTPS/Tailscale และขั้นตอนอนุมัติทีวีจริง

ผลทดสอบอัตโนมัติและภาพตัวอย่างจาก Android Views ไม่ใช้แทนผลตรวจอุปกรณ์จริง
