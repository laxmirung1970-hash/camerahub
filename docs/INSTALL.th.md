# ติดตั้ง CameraHub

## Windows: ทดลองก่อนโดยไม่ใช้กล้องจริง

เปิด `Start-CameraHub.cmd` หรือใช้ `scripts/Start-Demo.ps1` ต้องมี Docker Desktop แบบ Linux containers

ระบบผูกเว็บไว้ที่ `127.0.0.1:17800` จึงไม่เปิดให้เครื่องอื่นใน LAN เข้าถึงโดยอัตโนมัติ ตัวกลาง go2rtc ไม่มีพอร์ตจัดการที่เผยแพร่สู่โฮสต์ บัญชีจริงถูกปิดในโหมดสาธิต

หากย้ายไป Windows เครื่องอื่น ให้แตก `CameraHub-Windows-1.0.0.zip` รัน `Load-Images.ps1` แล้วเปิด `Start-CameraHub.cmd` ไม่ต้องมี Go หรือ Android SDK ชุด ZIP ไม่รวมบัญชี รหัสผ่าน หรือฐานข้อมูล

การตั้งค่าครั้งแรกใช้รหัสที่ `scripts/Show-SetupCode.ps1` แสดง แล้วตั้งรหัสเจ้าของอย่างน้อย 8 ตัวอักษร

## Windows: เชื่อม Tapo จริงก่อนลง NAS

1. ให้ Windows และกล้องอยู่ในเครือข่ายที่ติดต่อกันได้ เปิด Docker Desktop
2. เปิด File Explorer ไปที่โฟลเดอร์โครงการแล้วดับเบิลคลิก `Start-CameraHub-Live.cmd` โปรแกรมเปิด **http://127.0.0.1:17801** เป็น `live` แยกจากโหมดสาธิตที่พอร์ต 17800 การคลิกลิงก์ไฟล์ในแชต Codex จะเปิดดูโค้ดแทนการรัน
3. ครั้งแรกใช้รหัสเริ่มต้นที่หน้าต่างคำสั่งแสดง สร้างบัญชีเจ้าของ CameraHub และตั้งรหัสผ่านอย่างน้อย 8 ตัวอักษร หากต้องดูรหัสอีกครั้ง รัน:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Show-SetupCode.ps1 -Mode windows-live
```

4. ใน Tapo สร้าง Camera Account ของกล้องแต่ละเครื่องแล้วดู IP ที่ Device Settings → Device Info ใช้ข้อมูลจริงที่แอปแสดง ไม่คัดลอก IP ตัวอย่าง
5. ใน CameraHub เข้า **ตั้งค่า → เชื่อมกล้อง → เพิ่ม Tapo ด้วย IP โดยตรง** กรอก IP, ชื่อกล้อง, Camera Account และรหัสผ่านกล้อง กด **เชื่อมต่อ IP นี้** จากนั้นกด **ตรวจภาพ** ในรายละเอียด ทดลองเสียง/หมุน/หยุดก่อนเพิ่มเครื่องถัดไป
6. โหมดนี้เข้าถึงจาก Windows เครื่องที่รันเท่านั้น มือถือเปิด `127.0.0.1` ของ Windows ไม่ได้ ให้ใช้ชุด NAS/HTTPS สำหรับมือถือและทีวีภายหลัง

Windows/Docker ต้องเปิดระหว่างใช้งาน ไม่มีการสแกนเครือข่ายจนกว่าเจ้าของจะเปิดการเชื่อมต่อแบบค้นหา การเพิ่มด้วย IP ติดต่อเฉพาะ IP ที่กรอก การค้นหา multicast อาจข้าม Docker Desktop ไม่ได้

หยุด: `scripts/Stop-Live.ps1` · ตรวจสถานะ: `scripts/Check-System.ps1 -Mode windows-live` ข้อมูลอยู่ใน volumes `camerahub-windows-live_live-data` และ `camerahub-windows-live_live-gateway` ไม่รวมในชุดส่งมอบ ไม่ใช้ `down -v` เพราะลบข้อมูล การย้ายทะเบียนกล้องไป NAS ใช้สำรอง/กู้คืนโหมด live ตามคู่มือด้านล่าง

## DS223: ทำเมื่อพร้อมทดสอบจริง

ยังไม่ได้ทำขั้นตอนเหล่านี้บน NAS ของคุณ

1. เลือกโฟลเดอร์ใหม่ เช่น `/volume1/docker/camerahub` โดยตรวจชื่อ volume จริงก่อน ไม่ทับโปรเจกต์เดิม
2. คัดลอก `camerahub-nas-arm64-images.tar` และ `compose.nas.yaml` ลงโฟลเดอร์นี้
3. นำเข้า images ผ่าน Container Manager หรือ SSH:

```sh
docker load -i camerahub-nas-arm64-images.tar
docker compose -f compose.nas.yaml up -d
```

สร้าง Project ใน Container Manager โดยใช้ `compose.nas.yaml` ได้เช่นกัน ไม่ต้อง build โค้ดบน NAS

4. ติดตั้ง Tailscale แบบ native บน DSM ตาม [เอกสารสำหรับ Synology](https://tailscale.com/docs/integrations/synology) แล้วเข้าสู่ tailnet ของเจ้าของ
5. ตั้ง HTTPS ด้วย Tailscale Serve บน NAS:

```sh
tailscale serve --bg http://127.0.0.1:8080
```

อาจต้องใช้ path ของ `tailscale` ตามแพ็กเกจและสิทธิ์ผู้ดูแล เปิด HTTPS certificates ในบัญชี Tailscale ตามขั้นตอนของผู้ผลิตเมื่อระบบแจ้ง ห้ามข้ามคำเตือนใบรับรองของเบราว์เซอร์

6. เปิด URL HTTPS ที่ Tailscale แสดงจากมือถือ/Windows ที่เข้า tailnet เดียวกัน
7. รหัสเริ่มต้นอยู่ใน `data/live-setup-code.txt` บน NAS (ไฟล์นี้ถูกลบเมื่อสร้างเจ้าของสำเร็จ) ตั้งชื่อและรหัสผ่านเจ้าของแอป
8. เข้า “เชื่อมกล้อง” แล้วเพิ่มบัญชี ค่อยเปิดการค้นหา/ซิงก์

Compose นี้ใช้ host networking สำหรับ ONVIF multicast แต่เว็บรับที่ `127.0.0.1:8080` และ go2rtc ที่ `127.0.0.1:1984` ใช้ Tailscale Serve เป็นทางเข้าผู้ชม ไม่ต้องเปิด RTSP/ONVIF ออกอินเทอร์เน็ต Secure cookies เปิดไว้สำหรับ HTTPS

หากพอร์ตชนกับโปรแกรมเดิม ให้แก้ `APP_LISTEN` และคำสั่ง Serve ให้ตรงกันก่อนเริ่ม ห้ามเปลี่ยนเป็นพอร์ตสาธารณะเพื่อแก้ชั่วคราว

## เชื่อม Tapo

- เปิดกล้องในแอปเดิม → Device Settings → Advanced Settings → Camera Account (ขึ้นกับรุ่น)
- ใช้บัญชีกล้องนี้ใน CameraHub แยกจากรหัสผ่าน TP-Link ID
- เปิดค้นหา ONVIF หรือใช้ช่องเพิ่มด้วย IP โดยตรง
- ใน Docker Desktop บน Windows multicast อาจข้ามไป LAN ไม่ได้ ใช้ IP โดยตรงหรือตรวจจริงบน NAS ที่ใช้ host networking
- กด “ตรวจภาพ” จากรายละเอียดกล้อง ผลตรวจสตรีมไม่ยืนยันเสียง/มอเตอร์ ต้องทดลองแยกแล้วทำเครื่องหมายตรวจรับ

### กดเชื่อมต่อแล้วเหมือนไม่เกิดอะไรขึ้น

รุ่นปรับปรุงแสดง “กำลังเชื่อมต่อ…” และผลค้างใต้ปุ่มเพิ่มด้วย IP รอได้ประมาณ 30 วินาที ถ้าติดต่อกล้องได้แต่ยืนยันไม่ผ่าน ให้เปิด Tapo ของกล้องตัวเดียวกัน → Advanced Settings → Camera Account → Account Information ตรวจ Username และใช้รหัสผ่าน Camera Account นั้น (แยกจากชื่อกล้องและรหัสเข้า CameraHub) กรอกรหัสผ่านบนหน้าเว็บเอง ไม่ส่งผ่านแชต ข้อความ HTTP/auth ไม่ได้ยืนยันว่ารหัสผ่านผิดเพียงสาเหตุเดียว ยังต้องตรวจบัญชี เวลา และความเข้ากันได้ของโปรโตคอลตามผลจริง

## เชื่อม Xiaomi

- เข้าบัญชีบนหน้าตั้งค่า CameraHub โดยตรง ระบบไม่บันทึกรหัสผ่าน Xiaomi ลงฐานข้อมูลแอป แต่ go2rtc เก็บโทเคนในโฟลเดอร์ gateway ที่จำกัดสิทธิ์
- ทำขั้นตอน CAPTCHA/รหัสยืนยันด้วยตัวเอง เลือกรหัสบัญชีและ Region ให้ตรงกับ Xiaomi Home แล้วบันทึกเปิดซิงก์
- บางบัญชี/กล้องที่แชร์อาจดึงรายชื่อได้ไม่ครบ หยุดตรวจรายตัวและบันทึกรุ่นก่อน ไม่สรุปว่าครบจากยอดบัญชี
- การหมุนเริ่มเปิดเฉพาะโปรไฟล์ที่รู้จัก รุ่นอื่นเลือก “ทดลอง MISS ทีละก้าว” ได้จากรายละเอียดหลังตรวจความเข้ากันได้ การไม่ตอบรับจะเป็นข้อผิดพลาด ไม่รายงานว่าสำเร็จ
- Xiaomi แบบ MISS ใช้การขยับทีละก้าว หยุดส่งคำสั่งเมื่อปล่อยปุ่ม ไม่อ้างว่าได้ส่งคำสั่งหยุดมอเตอร์ที่ยังไม่มีมาตรฐานร่วม

## เมื่อภาพเดิมเล่นไม่ได้

รายละเอียดกล้อง → ชื่อกล้องและความสามารถ → การเล่นวิดีโอ → แปลงเป็น H.264

ค่าเริ่มต้นส่งต่อภาพเดิม การแปลงลดขนาดเป็นกว้าง 640 สำหรับหลายภาพ และ 1280 สำหรับ HD ใช้ CPU เพิ่ม ต้องเริ่มทีละตัวบน DS223 ถ้าเครื่องไม่พอให้กลับส่งต่อภาพเดิมและบันทึกผล ไม่รับประกันการแปลงสี่กล้องพร้อมกัน

เว็บใช้ MSE ผ่าน HTTPS เป็นค่าเริ่มต้นเพื่อให้ผ่าน Tailscale/พร็อกซีโดยไม่เปิดพอร์ต UDP มี HLS สำรองสำหรับอุปกรณ์อื่น และมี WebRTC ในโค้ดสำหรับตรวจเส้นทางเครือข่ายภายหลัง (`APP_WEBRTC=true`) ยังไม่ตรวจ WebRTC กับอุปกรณ์จริง

## Mi TV / Android TV

1. ติดตั้ง Tailscale จากช่องทางทางการ เข้าสู่ tailnet เดียวกับ NAS
2. ติดตั้ง `camerahub-tv-1.1.0.apk` ผ่านช่องทางติดตั้ง APK ส่วนตัวของทีวี
3. เปิด CameraHub TV แล้วกรอก URL HTTPS ของ NAS
4. ทีวีแสดงรหัส → บนมือถือเข้า “ตั้งค่า → ทีวีและอุปกรณ์” → ตรวจรหัสให้ตรงแล้วอนุมัติ
5. เริ่มดู 4 ภาพ ใช้ลูกศรเลือกกรอบ → OK ดูเดี่ยว → Back กลับ 4 ภาพ; กดลงจากแถวล่างเพื่อเปลี่ยนชุดหรือเปิดรายชื่อ
6. เปิดเสียงเฉพาะกล้องที่เลือก ยกเลิกสิทธิ์ทีวีได้จากหน้าตั้งค่ามือถือ

APK ลงนามสำหรับติดตั้งส่วนตัว กุญแจอยู่ใน `data/signing/` ของเครื่องพัฒนาและไม่อยู่ใน ZIP เก็บสำรองกุญแจไว้เป็นส่วนตัวเพื่อให้ APK รุ่นถัดไปอัปเดตทับได้ รูปแบบวิดีโอและจำนวนตัวถอดรหัสต้องทดสอบบนทีวีจริง

คู่มือรีโมต การสลับชุดอัตโนมัติ และการหมุน: [CameraHub TV 1.1.0](TV_GUIDE.th.md) — URL `127.0.0.1:17801` ของ Windows ใช้กรอกบนทีวีไม่ได้ ต้องเตรียม URL HTTPS ของเครื่องกลางก่อน

## สำรอง / กู้คืน / กลับเวอร์ชัน

- ตั้งค่า → ระบบและสำรอง → ตั้งรหัสไฟล์อย่างน้อย 12 ตัวอักษร → ดาวน์โหลด `.cambackup`
- เก็บรหัสแยกจากไฟล์ ไฟล์รวมข้อมูลเข้ากล้องและโทเคนที่เข้ารหัส ไม่รวมวิดีโอและบัญชีเจ้าของ
- กู้คืนได้เฉพาะโหมดเดียวกัน ต้องกรอกรหัสและพิมพ์ `RESTORE` การกู้คืนแทนที่ทะเบียน/บัญชีกล้องปัจจุบัน ควรสำรองชุดปัจจุบันก่อน
- กู้คืนแล้ว restart `gateway` เพื่อโหลดโทเคนจากไฟล์ เช่น `docker compose -f compose.nas.yaml restart gateway`
- เก็บ images รุ่นเดิมและไฟล์สำรองก่อนอัปเดต ตั้ง tag รุ่นที่ต้องการใน Compose แล้วเริ่มใหม่ ไม่ใช้ `down -v` เพราะลบ volume
- ฐานข้อมูลใช้ schema รุ่นแรก หากเปลี่ยน schema ในรุ่นหน้า ต้องเขียน migration และตรวจย้อนเวอร์ชันก่อนส่งมอบ
