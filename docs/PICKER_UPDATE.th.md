# เลือกกล้อง จัดลำดับ และสถานะตรวจระบบ — 2 พฤศจิกายน 2026

**อัปเดต 3 พฤศจิกายน:** เปลี่ยนทางรับภาพเป็น Docker + Windows UDP relay แล้ว ตรวจภาพและมอเตอร์จริงผ่าน12กล้อง รายละเอียด [ผลตรวจล่าสุด](LIVE_CHECK_2026-11-03.th.md) สถานะตัวกลางค้าง/รอรีสตาร์ตข้างล่างเป็นประวัติ

## ใช้หน้าจอใหม่

เปิด [CameraHub บน Windows เครื่องนี้](http://127.0.0.1:17801/) แล้วรีเฟรชหนึ่งครั้ง

1. ในรายการ **เลือกกล้อง** ด้านขวา ติ๊กช่องหน้ากล้องได้สูงสุด 4 ตัว เลข 1–4 คือช่องภาพตามลำดับที่เลือก เอาเครื่องหมายถูกออกก่อนเปลี่ยนเป็นตัวอื่น ระบบจำชุดที่เลือกในเบราว์เซอร์นี้หลังเปิดหน้าใหม่
2. กดชื่อกล้องเพื่อดูเดี่ยว ส่วนช่องติ๊กใช้เลือกชุด 4 ภาพ บนมือถือมีปุ่มไปยังรายการเลือกกล้องและกลับไปดูภาพ
3. กด **จัดลำดับ** แล้วใช้ลูกศรขึ้น/ลง จากนั้นกด **เสร็จจัดลำดับ** ลำดับรายชื่อบันทึกที่เครื่องกลาง หากกรองรายชื่อ ลูกศรจะสลับกับรายการที่มองเห็นข้างเคียง ชุดเลือกเองยังคงช่องตามลำดับที่ติ๊ก ไม่เปลี่ยนช่องตามการจัดรายชื่อ
4. กดรูป **ดินสอ** ข้างชื่อ กรอกชื่อที่จำง่าย แล้วกด **บันทึกชื่อ** ชื่อรุ่นยังแสดงถัดจากชื่อของคุณ ไม่เปลี่ยน Camera Account และชื่อไม่หายเมื่อซิงก์ รุ่นที่ยังจับคู่ชื่อผลิตภัณฑ์ไม่ได้จะแสดงรหัสรุ่นจริง
5. กล้องที่รับภาพไม่ได้จะแสดง **พื้นดำ พร้อมเหตุผลและวิธีตรวจ** ในช่องนั้น เช่น ยืนยันบัญชีไม่ได้ รูปแบบภาพไม่รองรับ รับภาพไม่ทัน หรือเชื่อมตัวกลางวิดีโอไม่ได้ ไม่แสดงภาพเก่าค้างเป็นภาพสด

เลือก **ครั้งละ 4** เพื่อกลับไปสลับชุดอัตโนมัติ หรือ **ทุกกล้อง** เพื่อแสดงทุกช่องพร้อมกัน การเปิดทุกช่องยังไม่ผ่านการรับรองความเสถียรบนเครื่องนี้

## การหมุนกล้อง: ยังไม่ผ่านตรวจครบทุกตัว

เพิ่มขั้นอ่านตำแหน่งมอเตอร์ Xiaomi ในหน้าดูเดี่ยว ก่อนเปิดปุ่มหมุนให้กล้องที่ตอบคำสั่งได้ แก้การอ่านชนิดคำตอบและข้อมูลท้ายข้อความในตัวกลาง พร้อมทดสอบข้อมูลตอบกลับจำลอง การอ่านตำแหน่งได้หมายถึงตรวจความสามารถ ไม่ใช่ยืนยันว่ามอเตอร์เคลื่อนจริงทุกทิศทาง

รอบนี้ตัวกลาง Windows มีการเชื่อมต่อขาออกค้าง ทั้ง RTSP ไป Tapo และ HTTP ไป Xiaomi จึงไม่ได้วิดีโอสำหรับตรวจการหมุนจริง เปรียบเทียบโปรแกรมเดิมแล้วยังพบอาการ ไม่มีหลักฐานพอระบุว่าเกิดจากกล้อง ไฟร์วอลล์ หรือไดรเวอร์ใด ไม่ได้เปลี่ยนไฟร์วอลล์หรือโปรแกรมป้องกันเครื่อง และไม่ได้รีเซ็ตกล้อง

ผล Tapo92 หมุนและอ่านตำแหน่งได้ในรอบก่อนเป็นประวัติ ไม่ใช้แทนผลตรวจรอบนี้ ตัวรับสัญญาณ Indoor Receiver ไม่ใช่รายการที่ควรรับรองว่ามีมอเตอร์หมุน

## สถานะเครื่องและการทำต่อ

- เว็บเปิดได้ ข้อมูลเดิม 17 รายการและบัญชียังอยู่ ชุดหน้าจอที่เตรียมคือ Tapo92 / H1 / H3 / Mi 360°
- ยังไม่เปิดตัวกลางเพิ่มระหว่างรอแก้ Windows มีโปรเซสจากการตรวจที่ Windows ยังถือค้างแม้สั่งหยุด จึงไม่อ้างว่าหยุดได้สะอาดทั้งหมด
- เสนอให้เจ้าของบันทึกงานอื่นและรีสตาร์ต Windows เองเมื่อพร้อม **ยังไม่ได้ทำและไม่รับรองว่าจะหาย** หลังกลับมาให้เริ่มจาก `Start-CameraHub-Live.cmd` แล้วตรวจ Tapo92 และ Xiaomi หนึ่งตัวก่อน จึงค่อยตรวจหมุนทีละกล้อง
- ไม่ต้องเปลี่ยนรหัสหรือเชื่อมบัญชี Xiaomi/Tapo ซ้ำเพื่อทำขั้นนี้
- ตัวกลางใช้ API loopback 17992 และ RTSP loopback 18562 ตามไฟล์ตั้งค่าส่วนตัว API มีการยืนยันตัวตน หน้าดูภาพยังใช้ 17801 ตามเดิม
- ตัวเปิดเลือก `go2rtc.startup.exe` ที่ตรวจ SHA-256 แล้วคัดลอกเฉพาะโปรแกรมไป `%LOCALAPPDATA%\CameraHub\runtime\<sha>\go2rtc.exe` บัญชีและกุญแจคงอยู่ในโฟลเดอร์ data ของ workspace
- ตรวจความพร้อมตัวกลางจาก `startup: ready` หลังโหลดโมดูลครบ ป้ายนี้ไม่รับรองว่ากล้องทุกตัวมีภาพหรือหมุนได้

## หลักฐานทดสอบ

ผ่าน Go tests 25 ฟังก์ชันทดสอบและ go vet, Web Vitest 4 ข้อ, TypeScript/Vite และ Docker amd64 build รวมการตรวจเจ้าของระบบก่อนบันทึกลำดับ/อ่านมอเตอร์ การรักษาลำดับหลังซิงก์ การปฏิเสธคำตอบมอเตอร์ผิดรูป และไม่เปิดเผย URL/ข้อมูลลับจาก error

Chrome ตรวจเลือกครบ 4 ช่องและจำค่าหลังโหลดใหม่ ปฏิเสธกล้องตัวที่ 5 จัดลำดับแล้วโหลดใหม่ยังอยู่ เปลี่ยนชื่อภาษาไทยแล้วโหลดใหม่ยังอยู่และคืนชื่อเดิม แสดงชื่อรุ่นและพื้นดำพร้อมเหตุผล ตรวจหน้าจอ 390 CSS px ไม่ล้นในรอบตรวจมือถือจำลอง

การทดสอบสคริปต์อ่านตำแหน่งบนกล้องจริงรอบนี้ **ไม่ผ่านขั้นรับวิดีโอ** ข้อความ PASS ของตัวรันทดสอบนั้นหมายถึงรันครบรายการ ไม่ใช่กล้องผ่านตรวจ ไม่มีการเปิด PTZVerified ให้กล้องจริงเอง

ยังไม่ตรวจรับ iPhone/Android/รีโมตทีวี/NAS จริง และยังไม่ได้สร้าง ZIP, ARM64 หรือ APK ใหม่สำหรับงานรอบนี้ ห้ามนำชุด releases เก่าไปอ้างว่ามีฟังก์ชันล่าสุดครบ

แหล่งอ้างอิงสำหรับการแก้กรอบคำตอบมอเตอร์: [รายงานคำสั่ง Xiaomi C300](https://github.com/AlexxIT/go2rtc/issues/2162) และ [ต้นฉบับการถอดรหัสคำตอบ](https://raw.githubusercontent.com/bkulpa/go2rtc/feat/xiaomi-auto-center/pkg/xiaomi/miss/client.go) การรองรับรุ่นอื่นยังต้องตรวจอุปกรณ์จริง
