## ข้อมูล Tapo ที่ได้รับเพิ่มเติม 1 พฤศจิกายน 2026

เจ้าของสร้าง Camera Account ของทั้งสองเครื่องแล้ว และแจ้งชื่อ/IP ดังนี้ ยังไม่ผูกชื่อเหล่านี้เข้ากับ serial number หรือรหัสตรวจรับจนกว่าจะยืนยันจากการเชื่อมต่อจริง

| ชื่อใน Tapo | IP (ตัวอย่าง ไม่ใช่ค่าจริง) | ผลตรวจการเข้าถึงจาก Windows |
|---|---|---|
| Tapo91 | 192.0.2.91 | TCP 2020 และ 554 ติดต่อได้ |
| Tapo92 | 192.0.2.92 | TCP 2020 และ 554 ติดต่อได้ |

ผล TCP นี้ไม่ได้ยืนยันภาพ เสียง หรือการหมุน ไม่มีรหัสผ่านกล้องในเอกสาร เครื่องกลาง Windows live เปิดอยู่ที่ `http://127.0.0.1:17801` IP อาจเปลี่ยนได้หาก DHCP แจกใหม่

**ความคืบหน้าเพิ่มเติมวันเดียวกัน:** เจ้าของตั้งบัญชี CameraHub แล้ว ตรวจ ONVIF `GetSystemDateAndTime` แบบไม่ใช้บัญชีของทั้งสอง IP ได้ HTTP 200 จาก Windows และเครือข่าย Docker ของ app จากนั้นลองเพิ่ม Tapo91 ด้วยบัญชีที่เจ้าของกรอก ได้ HTTP 400 พร้อม SOAP fault กลุ่มยืนยันบัญชีไม่ผ่าน ยังไม่เพิ่มทะเบียนกล้องสำเร็จและยังไม่ตรวจภาพ/เสียง/หมุน ต้องให้เจ้าของตรวจ Camera Account ใน Tapo แล้วทดลองใหม่ ไม่ได้ยืนยันว่ารหัสผ่านผิดแน่นอน

**ผลตรวจถัดมา:** เจ้าของแจ้ง Verify ผ่าน แต่ยังไม่ยืนยัน Username จริงจากหน้ามือถือ RTSP และ ONVIF ปฏิเสธคู่บัญชีที่อยู่ในฟอร์ม CameraHub เหมือนกัน จึงรอภาพหน้า Camera Account หลังปิดหน้าต่าง Not Now / Update Password โดยไม่แสดงรหัสผ่าน ยังไม่เพิ่มกล้องหรือทดสอบภาพสำเร็จ

**ผลล่าสุดหลังได้รับภาพหน้าบัญชี:** ยืนยัน Username ของ Tapo91 เป็น `tapo-user-1` แก้ชื่อที่มีเลข 0 เกินแล้วลงทะเบียนกล้องใน CameraHub สำเร็จ อ่านรุ่น C520WS/ความสามารถ PTZ ได้ แต่ยังไม่ตรวจผ่านภาพ เสียง หรือการหมุน ตรวจพบการเลือก low เป็น stream8 จึงแก้ให้เลือก stream1/stream2 เมื่อกล้องประกาศช่องเหล่านี้ ช่วงตรวจต่อ .91 หยุดรับ TCP 2020/554 ทั้งจาก Windows และ Docker ขณะที่ .92 ยังตอบ รอเจ้าของตรวจภาพสดใน Tapo และ Camera Account เป็น On ก่อนทดสอบต่อ ไม่มีการรีเซ็ตหรือเปลี่ยนรหัสผ่านกล้อง

**ก่อนพัก:** เจ้าของเพิ่ม Tapo92 ด้วย Username `tapo-user-2` และกรอกรหัสผ่านเอง ตรวจ UI ยืนยันเพิ่มสำเร็จและรายการรวม 2 กล้องแล้ว หยุด app/gateway โดยรักษาข้อมูลตามคำขอ ทั้งสองเครื่องยังรอตรวจภาพ/เสียง/หมุนครั้งหน้า ไม่ถือว่าสถานะลงทะเบียนยืนยันผลสตรีมจริง

## วิธีเชื่อมและสิ่งที่ยังต้องพิสูจน์

- **Tapo C520WS:** ผู้ผลิตระบุ RTSP/ONVIF ใช้ Camera Account ใน Tapo และตัวเชื่อม ONVIF ที่เตรียมไว้ เริ่มหนึ่งเครื่อง ตรวจภาพคุณภาพต่ำ/สูง เสียง การหมุน และการหยุดก่อนขยายอีกเครื่อง ยังไม่ถือว่าตรวจผ่านกับเครื่องเจ้าของ
- **Xiaomi C300 / C302:** เริ่มตัวอย่างอย่างละหนึ่งเครื่องผ่านตัวเชื่อม Xiaomi ที่เตรียมไว้ ต้องอ่าน model ID จริงจากบัญชี/อุปกรณ์ รวมถึง Region และเฟิร์มแวร์ ชื่อทางการตลาดไม่เพียงพอให้ยืนยันโปรโตคอลภาพหรือเปิด PTZ อัตโนมัติ
- **Xiaomi C300 Dual:** ผู้ผลิตระบุเลนส์คงที่และเลนส์หมุน ตรวจว่าตัวเชื่อมเปิดเลนส์ใดได้บ้าง ภาพรวมกันหรือแยก stream และคำสั่งหมุนไปยังเลนส์ที่ถูกต้อง ระบบปัจจุบันมี low/high ต่อหนึ่งรายการกล้อง ยังไม่มีการยืนยันการเลือกเลนส์แบบ Dual จึงต้องตรวจ protocol แล้วจึงปรับการผูก channel หากจำเป็น
- **m360 camera (1080p):** เก็บชื่อตามที่แจ้ง ยังไม่ตีความเป็นรุ่น Mi 360 รุ่นใดแน่นอน เมื่อสะดวกใช้หน้าข้อมูลอุปกรณ์ใน Xiaomi Home หรือ model ID ที่ระบบดึงได้เพื่อแยกรุ่น ไม่ต้องถอดกล้อง
- รุ่นที่โฆษณาบันทึกลง NAS ไม่ได้ยืนยันว่าเปิดภาพสดจากแอปภายนอกได้ ต้องทดสอบตัวเชื่อมแยกจากคุณสมบัติสำรองคลิป

**จำนวนเครื่องกับจำนวนภาพแยกกัน:** C300 Dual สองเครื่องยังนับเป็นสองเครื่อง หากเปิดแยกเลนส์ได้ครบ อาจมีภาพจากเลนส์รวม 18 ช่องจาก 16 เครื่อง แต่ยังไม่รับรองจำนวนช่องที่ตัวเชื่อมเปิดได้ ดูพร้อมกันยังคงเป้าหมาย 1–4 ภาพ ไม่ใช่เปิดทุกช่องพร้อมกันบน DS223

## ลำดับตรวจเมื่อเจ้าของสะดวก

1. Tapo C520WS หนึ่งเครื่อง เพื่อยืนยันทาง RTSP/ONVIF
2. Xiaomi C300 หนึ่งเครื่อง ซึ่งเป็นกลุ่มใหญ่ที่สุด
3. Xiaomi C302 หนึ่งเครื่อง ตรวจความต่างของโปรโตคอล/เฟิร์มแวร์
4. Xiaomi C300 Dual หนึ่งเครื่อง ตรวจทั้งสองเลนส์และการผูกคำสั่งหมุน
5. m360 camera (1080p) ตรวจรุ่นจริงและการเปิดภาพ
6. ขยายครบ 16 เครื่อง จับคู่ชื่อห้องกับ device ID ที่ค้นพบ ป้องกันรายการซ้ำ แล้ววัดโหลด DS223 และตรวจอุปกรณ์ผู้ชมจริง

ผลตรวจรายเครื่องเริ่มต้นทั้งหมดเป็น `pending` การค้นพบชื่อกล้องไม่ใช่ผลผ่านภาพ/เสียง/หมุน หากกล้องไม่รองรับฟังก์ชันใดให้บันทึก `unsupported` พร้อมเหตุผล ไม่เปลี่ยนเป็นผ่าน

## ขอบเขตการปรับปรุงครั้งนี้

อัปเดตรายการอุปกรณ์ คู่มือเตรียม และบันทึกงานต่อเท่านั้น ไม่เชื่อมบัญชี ไม่ค้นหาเครือข่าย และไม่แก้ NAS/เฟิร์มแวร์ โหมดสาธิตและรายงานตรวจวันที่ 28 ตุลาคมยังเป็น **15 กล้องจำลอง** ตามที่ตรวจจริง ชุดโปรแกรม/APK/images ไม่ได้เปลี่ยนความสามารถจากการเพิ่มข้อมูลรุ่น เอกสารใน ZIP ได้ปรับปรุงตามรายการนี้
