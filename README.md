## เปิดทดลองบน Windows

1. เปิด Docker Desktop ให้พร้อม
2. ดับเบิลคลิก `Start-CameraHub.cmd` หรือรัน:

```powershell
# เปิด PowerShell ในโฟลเดอร์โครงการก่อน
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Start-Demo.ps1
```

3. เปิด **http://127.0.0.1:17800**
4. เมื่อตั้งค่าครั้งแรก ดูรหัสด้วย `scripts/Show-SetupCode.ps1` แล้วตั้งชื่อและรหัสผ่านของแอปนี้
5. เลือกดู 1–4 ภาพ ทดลองเสียง ขยาย HD หมุนแบบจำลอง เพิ่มกล้อง หรือเปลี่ยนสถานะกล้องในหน้ารายละเอียด

ระบบที่ส่งมอบรอให้คุณตั้งเจ้าของเอง บัญชีชั่วคราวที่ใช้ตรวจงานถูกล้างแล้ว โดยเก็บกล้องจำลองและการตั้งค่าไว้

หยุดระบบโดยไม่ลบข้อมูล:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/Stop-Demo.ps1
```

ตรวจสถานะ: `scripts/Check-System.ps1` · สร้างใหม่หลังแก้โค้ด: `scripts/Start-Demo.ps1 -Rebuild`

## เชื่อมกล้องจริงบน Windows

ดับเบิลคลิก **`Start-CameraHub-Live.cmd`** จาก File Explorer เปิด **http://127.0.0.1:17801** ตัวเปิดแสดงรหัสตั้งเจ้าของครั้งแรกในหน้าต่างคำสั่ง ตั้งชื่อและรหัสผ่าน CameraHub อย่างน้อย 8 ตัวอักษร แล้วเข้า **ตั้งค่า → เชื่อมกล้อง → เพิ่ม Tapo ด้วย IP โดยตรง** กรอก IP และ Camera Account ของแต่ละกล้อง การคลิกลิงก์ไฟล์ในแชต Codex จะเปิดดูโค้ด ให้ใช้ File Explorer เมื่อต้องการรันตัวเปิด

โหมดนี้ใช้ข้อมูลจริงแยกจาก demo เปิดดูบน Windows เครื่องนี้เท่านั้น เหมาะกับตรวจ Tapo ทีละเครื่องก่อนลง NAS ไม่เปิดการค้นหาหรือกรอกบัญชีให้อัตโนมัติ Docker Desktop อาจค้นหา ONVIF ผ่าน multicast ไม่พบ จึงเริ่มด้วย IP โดยตรง กล้องและ Windows ต้องอยู่เครือข่ายที่ติดต่อถึงกันได้

เปิดรหัสเริ่มต้นอีกครั้ง: `scripts/Show-SetupCode.ps1 -Mode windows-live` · ตรวจสถานะ: `scripts/Check-System.ps1 -Mode windows-live` · หยุดโดยเก็บข้อมูล: `scripts/Stop-Live.ps1`

Windows และ Docker ต้องเปิดอยู่ขณะใช้งาน หากต้องการเปิดจากมือถือ/ทีวีและนอกบ้าน ให้ติดตั้งชุด NAS และ HTTPS ตาม [คู่มือติดตั้ง](docs/INSTALL.th.md) อย่าเปลี่ยนพอร์ตเป็นสาธารณะเพื่อเปิดจากมือถือ

## ความสามารถ

- เว็บแอปภาษาไทย ติดตั้งเป็น PWA บนมือถือและ Windows ได้เมื่อใช้ HTTPS (localhost ใช้ได้บนเครื่องพัฒนา)
- ดูสด 1–4 ภาพ ค้นหา กลุ่มห้อง รายการโปรด เสียงทีละกล้อง และปุ่มหมุนแบบกดค้าง
- Android TV APK ใช้รีโมตและจับคู่รหัสโดยไม่ต้องกรอกรหัสผ่านกล้องบนทีวี
- โหมด demo/live แยกฐานข้อมูล คีย์ และข้อมูลเชื่อมต่อ
- Tapo: ONVIF discovery, บัญชีกล้อง, RTSP profiles และ ONVIF PTZ พร้อมเวลาหยุดในกล้อง
- Xiaomi: login พร้อม CAPTCHA/รหัสยืนยัน, เลือกบัญชี/Region, ซิงก์ และ PTZ ผ่านส่วนขยายชุมชนในรุ่นที่รองรับ
- ส่งต่อวิดีโอเดิมเป็นค่าเริ่มต้น เปิดแปลง H.264 เฉพาะรายกล้องเมื่อจำเป็น
- ค้นหา Tapo ทุก 2 นาที และซิงก์ Xiaomi ทุก 5 นาที **หลังเจ้าของเปิดใช้การเชื่อมต่อ**
- สำรองและกู้คืนไฟล์ `.cambackup` ที่เข้ารหัสด้วยรหัสแยกต่างหาก

## ข้อจำกัดที่ต้องทราบ

การเปิดได้ในแอปผู้ผลิตไม่ได้รับประกันว่าระบบภายนอกจะเปิดภาพหรือหมุนได้ Xiaomi ยังต้องขอกุญแจจากคลาวด์เมื่อเริ่มเชื่อมต่อ กล้องบางรุ่น/เฟิร์มแวร์อาจไม่รองรับ ส่วน Tapo ใหม่อาจต้องเปิด Camera Account ก่อน การพบรายชื่อไม่ได้ยืนยันว่าภาพพร้อมใช้

DS223 มี RAM 2 GB จึงยังไม่ยืนยันจำนวนการแปลงภาพหรือผู้ชมพร้อมกันจากผลบน Windows ต้องวัดที่เครื่องจริง เริ่มด้วยการส่งต่อภาพเดิมและทดสอบทีละกล้อง

รุ่นนี้ยังไม่บันทึกย้อนหลัง ไม่พูดผ่านกล้อง ไม่ติดตามคนด้วย AI และไม่ได้ลง Play Store ไม่แก้เฟิร์มแวร์หรือการตั้งค่ากล้องเดิมโดยอัตโนมัติ

## GitHub และ Vercel

โค้ดอยู่บน GitHub (สาธารณะ) ข้อมูลกล้อง บัญชี IP จริง บันทึกการทำงาน และภาพตรวจ อยู่ใน `private/`, `data/`, `.cache/` ซึ่งไม่ถูกส่งขึ้น Git ก่อน push ให้รัน `node scripts/check-private.mjs` (ตั้ง `git config core.hooksPath .githooks` ครั้งเดียวเพื่อให้ตรวจอัตโนมัติ) ในเอกสารใช้ IP ตัวอย่าง `192.0.2.x` และชื่อบัญชี `tapo-user` แทนของจริง

**Vercel โฮสต์เฉพาะหน้าเว็บ (UI) เท่านั้น** ไม่มีกล้อง วิดีโอ หรือฐานข้อมูลอยู่บน Vercel เครื่องกลางที่บ้าน (NAS/Windows) ต้องเปิดให้เข้าถึงผ่าน HTTPS เช่น Tailscale Funnel หรือ Cloudflare Tunnel แล้วตั้งค่าสองฝั่ง:

- บน Vercel (Root Directory = `web`): `VITE_API_BASE=https://<โดเมนเครื่องกลาง>` ค่าถูกฝังตอน build ต้อง deploy ใหม่เมื่อเปลี่ยน
- บนเครื่องกลาง: `APP_ALLOWED_ORIGINS=https://<โปรเจกต์>.vercel.app` (และ `APP_TRUSTED_PROXY` เมื่ออยู่หลัง tunnel) มิฉะนั้นเบราว์เซอร์จะถูกบล็อกด้วย CORS

ขั้นตอนทำเองทีละข้อ (Tailscale Funnel / Cloudflare Tunnel, แก้ compose, ตั้งค่า Vercel, ตรวจกล้องจริง) อยู่ใน [docs/REMOTE_SETUP.th.md](docs/REMOTE_SETUP.th.md) ถ้าไม่ตั้งค่าทั้งสองฝั่ง หน้าเว็บบน Vercel จะเปิดได้แต่แสดง "ขาดการเชื่อมต่อเครื่องกลาง" ซึ่งเป็นพฤติกรรมปกติ ข้อจำกัด: iPhone Safari ที่เล่น HLS แบบ native ส่ง Bearer token ข้ามโดเมนไม่ได้ ใช้ผ่าน NAS HTTPS โดเมนเดียวกันแทน

## สำหรับพัฒนาต่อ

- `web/`: React/TypeScript + Vite; `npm ci`, `npm run dev`, `npm run lint`, `npm test`, `npm run build`
- `backend/`: Go + SQLite; `go test ./...`, `go vet ./...`
- `android-tv/`: Kotlin + Media3; `scripts/Build-TV.ps1`
- `scripts/Build-NAS.ps1`: cross-build ARM64 โดยไม่ต้องใช้ NAS หรือเปิด privileged emulator
- `scripts/integration.mjs`: ตรวจสาธิตผ่าน API และ ffprobe; ปฏิเสธโหมด live และไม่แตะบัญชีที่ผู้ใช้ตั้งเอง
- `scripts/Test-Backend.ps1`: ทดสอบ backend ใน Docker
- `scripts/Package-Release.ps1`: ส่งออกชุดติดตั้ง ไม่รวมข้อมูลส่วนตัว

กล้อง วิดีโอ และข้อมูลทั้งหมดอยู่ภายในเครื่อง/เครือข่ายของคุณ โค้ดบน GitHub และหน้าเว็บบน Vercel ไม่มีข้อมูลกล้อง บัญชี หรือ IP จริง
